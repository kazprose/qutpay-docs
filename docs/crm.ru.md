# Подключение к CRM и другим системам

В Qut Pay два уровня. На первом — готовое решение, которое достаточно установить. На втором — подключение через собственный webhook или API вашей CRM. Работают оба, разница только во времени, которое уходит на подключение.

## Уровень 1. Готовое решение

Писать код не нужно. Устанавливаете, вставляете ключ, работает.

| Система | Что сделать |
|---|---|
| WordPress / WooCommerce | [Плагин](https://api.qut.kz/downloads/qutpay-for-woocommerce.zip) → [инструкция](https://api.qut.kz/docs/guide/wordpress) |
| OpenCart 4 | [Модуль](https://api.qut.kz/downloads/qutpay.ocmod.zip), README внутри архива |
| Tilda, Webflow, любая HTML-форма | Кабинет → Интеграции → «Форма-хук», вставить ссылку в поле action формы |
| n8n | [Два готовых workflow](https://api.qut.kz/downloads/qutpay-n8n.zip): создание счёта и приём событий |
| 1C | [Инструкция](https://api.qut.kz/docs/guide/1c) |
| Telegram | Платформенный бот: `/invoice 5000`, уведомления о платежах ([инструкция](https://api.qut.kz/docs/guide/telegram_bot)) |

## Уровень 2. Подключение через API

Готового модуля нет, но подключить можно. Условие одно: **CRM должна уметь отправлять HTTP-запросы наружу** (обычно это называется «исходящий webhook», «исходящий вебхук») или у вас должен быть разработчик.

| CRM | Как подключается |
|---|---|
| Bitrix24 | Исходящий webhook или n8n |
| amoCRM, Kommo | Webhook Digital pipeline или REST API |
| Altegio | Webhook и API |
| МойСклад, RetailCRM | REST API |
| Любая другая система | REST API + webhook |

Этот список — пример, а не ограничение. Подключается любая система, которая умеет отправлять HTTP-запросы.

### Поток

Есть два направления, обычно нужны оба.

**CRM → Qut Pay (создание счёта).** Когда сделка переходит на этап «Ожидает оплаты», CRM отправляет запрос в наш API, в ответе приходят ссылка на оплату и QR.

```
POST https://api.qut.kz/api/v1/invoices
X-API-Key: qp_live_…
Content-Type: application/json

{
  "amount": 25000,
  "description": "Сделка #1042",
  "externalOrderId": "1042",
  "metadata": { "dealId": "1042", "manager": "Айгүл" },
  "customer": { "phone": "77001234567", "name": "Клиент" }
}
```

В ответе приходят `payUrl`, `qrUrl` и `id`. Эту ссылку CRM отправляет клиенту.

Если CRM не умеет отправлять JSON, а умеет только простую форму — используйте «Форма-хук», он сам распознаёт поля `amount`, `phone`, `email`, `name`, `comment`.

**Qut Pay → CRM (уведомление об оплате).** Когда клиент платит, мы отправляем webhook на ваш адрес. Внутри `metadata` и `externalOrderId` возвращаются без изменений, поэтому сразу понятно, какая сделка оплачена.

```json
{
  "event": "invoice.paid",
  "invoice": {
    "id": "inv_…",
    "status": "paid",
    "amount": 25000,
    "externalOrderId": "1042",
    "metadata": { "dealId": "1042", "manager": "Айгүл" },
    "paidAt": "2026-09-10T05:12:00.000Z"
  }
}
```

Подпись — в заголовке `X-QutPay-Signature`, HMAC-SHA256. Примеры проверки: [Интеграция с сайтом](https://api.qut.kz/docs/guide/integration).

### Если у вас нет разработчика

Скопируйте целиком [инструкцию для ИИ-агента](https://api.qut.kz/docs/guide/for_ai), передайте её ChatGPT, Claude или Cursor и поставьте задачу: «подключи оплату Qut Pay к моей CRM». В инструкции есть все endpoint'ы, поля и список ошибок. Не пишите API-ключ и секрет webhook в чат, размещайте их только на своём сервере.

Тот же текст готов и в кабинете: Интеграции → «Инструкция для ИИ-агента» → «Скопировать вместе с задачей».

### Проверка

Сначала сделайте всё в режиме sandbox, он работает без реальных денег. Вручную меняя статус счёта в кабинете, вы проверите, что ваша CRM правильно обрабатывает webhook. Если всё верно, кабинет → Kaspi → подключите кассира и переключитесь в режим live.
